## 왜 브라우저가 필요한가

업로드된 일반 HTML에는 소설 본문이 없습니다. 페이지가 별도 응답을 받아 브라우저의
`[data-theme-novel-content]` 안 Shadow DOM에 표시합니다. 따라서 이 플러그인은
NAS의 전용 Chromium에 일반 페이지를 열고, 정상적으로 표시된 텍스트만 읽습니다.
쿠키를 채팅이나 FF 설정에 복사할 필요가 없습니다. 세션은 브라우저 프로필에만 남습니다.

- 페이지 URL: `/novel/작품번호?epage=페이지`
- 회차 URL: `/novel/작품번호/회차ID`
- 페이지 수를 6으로 고정하지 않습니다. 각 페이지의 링크를 순회하고 ID로 중복을 제거합니다.
- 제목/회차 ID/번호가 불일치하거나 같은 페이지가 반복되면 중단합니다.
- 보안 확인·접속 지역 제한·본문 검증 실패 시 자동 재시도하지 않습니다.
- 로그인·포인트 잠금 회차를 자동 구매하지 않습니다. unlock API를 호출하지 않습니다.
- 사이트의 인증/암호화 로직을 복제하거나 CAPTCHA를 자동 해결하지 않습니다.

## 포함 기능과 제한

설정 저장과 실행 분리, 전체 목록 분석, 수동 범위 선택, 자동 수집 목록, 예약 수집,
작품당 자동 수집 개수 제한, 파일명 번호 자릿수, 상단 작업 상태, 중지, SQLite 이력,
TXT/EPUB 합본/metadata.json/info.xml, 구버전 도메인 확인을 지원합니다.

수동 다운로드는 선택한 회차를 모두 대상으로 하며 자동 수집 개수 제한과 기존 이력의
건너뛰기를 적용하지 않습니다. 동일 경로 파일은 성공적으로 받은 후 원자적으로 교체합니다.
자동 수집은 저장된 파일의 존재·크기·해시를 확인하고 누락/0바이트/변경 파일을 다시 받습니다.

**0.1의 범위:** 텍스트 회차 전용입니다. 삽화가 있으면 누락된 TXT를 완료로 기록하지 않고
중단합니다. 표지/삽화 저장과 외부 메신저 알림, 기존 파일 이력 가져오기는 아직 없습니다.
파일명 자릿수를 바꾸고 재다운로드하면 이전 이름의 파일은 삭제하지 않습니다.
오류·인증·잠금에서 예약 수집은 대기합니다. 원인을 해결하고 수동 작업을 성공시키면 재개됩니다.
차단 중단 직전까지 저장한 TXT는 유지됩니다. EPUB은 작품 작업이 끝나거나 잠금 회차를 만났을 때 갱신합니다.

## 1. 전용 브라우저를 Portainer에 설치

`browser/compose.yaml`을 Portainer → Stacks → Add stack에 붙여 넣습니다.
스택 이름 예: `newtoki-browser`. 아래 환경 변수를 입력하세요.

| 변수 | 값 |
|---|---|
| NAS_LAN_IP | NAS의 실제 내부 IP, 예: `192.168.0.10` |
| BROWSER_PASSWORD | 이 전용 브라우저 화면에 사용할 비밀번호 |
| PUID | NAS 계정 UID (`id 사용자명`으로 확인) |
| PGID | NAS 계정 GID (`id 사용자명`으로 확인) |

`/volume1/docker/newtoki-browser`를 먼저 만들고 PUID/PGID 계정에 쓰기 권한을 주세요.
volume2를 사용한다면 YAML의 경로도 바꿉니다. FF의 다운로드 폴더와는 별개입니다.

배포 후 LAN에서 `https://NAS내부IP:3011`로 접속합니다. 사용자 이름은 `newtoki`,
비밀번호는 위에서 설정한 값입니다. 이미지 기본 HTTPS 인증서는 자체 서명 인증서이므로
주소·인증서가 본인 NAS의 것인지 확인하세요. 인터넷에 이 화면이나 CDP 포트를 공개하지 마세요.
공유기 포트포워딩이나 Cloudflare Tunnel에 연결할 필요가 없습니다.

그 화면 안 Chromium에서 먼저 `https://newtoki1.org/novel/58035/5397869`를 직접 열어 봅니다.
보안 확인이 있다면 이 전용 브라우저에서 직접 처리하세요. 본문이 정상 표시되는지 확인합니다.
평소 PC 브라우저에서 확인해도 이 전용 브라우저의 세션과는 공유되지 않습니다.

브라우저 자체가 사이트에서 차단되면 여기서 멈추세요. 이 구성은 Cloudflare 통과를 보장하지 않습니다.

## 2. FF와 브라우저 네트워크 연결

FF가 bridge 네트워크를 사용하는 경우 Portainer → Containers → **FF 컨테이너** →
Connected networks → Join a network에서 `newtoki_browser_net`을 추가합니다.
기존 FF 네트워크는 유지합니다. 재생성 시에는 FF 스택에도 이 외부 네트워크를 기록해야 합니다.

```yaml
# 기존 FF 스택에 병합할 예시. 서비스 이름/기존 네트워크는 원래 것을 유지하세요.
services:
  flaskfarm:
    networks:
      - default
      - newtoki_browser_net
networks:
  newtoki_browser_net:
    external: true
```

**FF가 `network_mode: host`인 경우** 위 방법으로 네트워크를 추가할 수 없습니다.
0.1.1 브라우저 예시에는 `127.0.0.1:9223:9223`이 이미 있습니다. 예전 스택에는 이 줄을 추가하고 FF의 브라우저 주소를
`http://127.0.0.1:9223`으로 설정합니다. 반드시 `127.0.0.1` 바인딩을 유지하세요.

CDP 9223은 내부 제어 포트입니다. 인증 기능이 없으므로 WAN/LAN 전체에 공개하지 않습니다.
브라우저에는 이 작업과 무관한 계정으로 로그인하지 마세요.

## 업데이트 후 Chromium이 안 열릴 때

`xmessage`에 「다른 컴퓨터(이전 컨테이너 ID)의 다른 Chromium 프로세스에서 프로필을 사용 중」이
표시되고 9222가 연결 거부되면 이전 컨테이너의 SingletonLock이 남은 것입니다.
원격 화면 서비스가 정상이어도 브라우저 자체는 이 대화상자에서 대기할 수 있습니다.

브라우저 스택의 `newtoki-browser` 서비스에 다음 한 줄을 추가하고 스택을 업데이트합니다.
FF 플러그인만 업데이트해도 기존 Portainer 스택은 자동으로 바뀌지 않습니다.

```yaml
services:
  newtoki-browser:
    container_name: newtoki-browser
    hostname: newtoki-browser
    # 기존 나머지 설정 유지
```

이전 브라우저 컨테이너가 같은 프로필을 사용하며 동시에 실행되지 않는 상태에서,
`https://NAS내부IP:3011`을 다시 열고 Chromium 경고창의
**「프로필 잠금 해제 및 다시 시작」(왼쪽 버튼)**을 누릅니다.
한글이 깨져 보이더라도 왼쪽 버튼이 잠금 해제, 오른쪽 버튼이 종료입니다.
프로필 전체를 삭제하지 않습니다. hostname을 고정하면 다음 재생성 때 컨테이너 ID가
바뀌어도 프로필에 기록되는 컴퓨터 이름이 바뀌지 않습니다.

브라우저 컨테이너 Console에서 다음 명령으로 내부 제어 포트를 확인합니다.

```sh
curl --noproxy '*' -sS --max-time 5 http://127.0.0.1:9222/json/version
```

JSON이 나온 뒤 FF Console에서 다음 명령을 실행합니다.

```sh
python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:9223/json/version', timeout=5).read().decode())"
```

9222는 정상이지만 9223이 실패하면 `newtoki-cdp-relay`를 재시작합니다.
`No such container` 또는 옛 컨테이너의 네트워크를 참조한다는 오류가 나면 Portainer에서
relay 컨테이너만 제거하고 기존 브라우저 스택을 다시 업데이트해 relay를 재생성합니다.
브라우저 프로필 볼륨이나 FF 컨테이너는 제거하지 않습니다.

## NAS 폴더에 직접 저장

FF에 연결된 경로를 저장 폴더로 지정하면 별도의 복사 작업 없이 NAS에 바로 저장됩니다.
설정의 **폴더 선택**으로 `/volume1`, `/volume2`, `/volume3`, `/data` 아래를 탐색할 수 있습니다.
경로가 존재한다고 모두 NAS 영구 볼륨인 것은 아니므로 FF 컨테이너의 Volumes 연결도 확인하세요.

사용자의 기존 FF Volumes 기준 예:

| FF 설정에 입력 | NAS에서 확인할 위치 |
|---|---|
| `/volume2/도서/북토끼` | `/volume2/도서/북토끼` |
| `/data/downloads/newtoki` | `/volume1/docker/flaskfarm/data/downloads/newtoki` |

원하는 상위 폴더를 선택하고 새 하위 폴더 이름을 붙인 뒤 **쓰기 확인 → 설정 저장**을 누르세요.
쓰기 확인은 기존 상위 폴더에 작은 임시 파일을 만들었다가 즉시 닫아 정리합니다.
새 다운로드 폴더는 실제 다운로드 시작 시 생성합니다. 기존 설정값은 사용자가 바꿀 때만 변경됩니다.

## 3. FF 플러그인 설치

플러그인 설치 주소:

```text
https://github.com/endells/newtoki_downloader
```

FF 컨테이너의 Console에서 **FF가 사용하는 Python**으로 의존성을 설치합니다.
기본 FF 환경은 다음 명령으로 설치할 수 있습니다. 가상환경을 쓰면 그 Python 경로로 바꾸세요.

```sh
python -m pip install 'websocket-client>=1.6,<2'
```

자동 pip 설치는 하지 않습니다. FF가 플러그인을 로드해도 의존성이 없다면 작업 시작 시
설치 안내만 표시합니다. 설치 후 FF를 재시작하세요.

## 4. 첫 테스트 순서

1. 전용 Chromium에서 440화 본문이 직접 보이는지 먼저 확인합니다.
2. FF → 북토끼 소설 다운 → 설정.
3. 기본 주소 `https://newtoki1.org`, 브라우저 주소 `http://newtoki-browser:9223` 입력.
4. 저장 폴더를 FF 컨테이너 안의 경로로 지정합니다. 예: `/data/downloads/newtoki`.
   NAS 호스트의 `/volume…` 경로를 쓰려면 FF에도 해당 볼륨이 연결되어 있어야 합니다.
5. 최초에는 자동 수집과 자동 도메인 확인을 끈 상태로 설정 저장.
6. 수동 다운로드 → `58035` → 작품 분석. 모든 페이지를 확인하므로 시간이 걸립니다.
7. 범위 `440 ~ 440` → 범위 선택 → 선택 회차 다운로드.
8. TXT에 실제 본문이 들어 있고 EPUB이 열리는지 확인한 뒤 범위를 늘립니다.
9. 자동 수집에 추가하고, 필요하면 설정에서 자동 수집을 켭니다.

정상 파일 예: `미궁탐험 101 [58035]/0440_440화 [5397869].txt`.
오류를 공유할 때는 FF의 상태 메시지와 단계만 알려주세요. 쿠키/프로필/HAR/페이지 토큰은 공유하지 마세요.
